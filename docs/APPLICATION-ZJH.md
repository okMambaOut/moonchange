## 项目简介

一次改动能否合并，往往不只取决于“谁负责这个目录”。修改核心代码可能还要满足审批人数、指定检查、变更行数和发布说明等条件。MoonChange 将这些约束写成策略文件，结合变更清单和评审证据，输出 passed、review 或 rejected，并列出需要哪些人审批、补哪些检查及材料。

项目以 MoonBit 实现策略解析、路径匹配、规则求值与报告生成，命令行负责读取输入。所有者规则按匹配具体程度选择，同分时后写的规则优先；治理规则则全部累加，审批人数取最大值、行数预算取最小值，不能用宽松规则抵消严格规则。重命名检查源路径和目标路径，避免只检查目标目录造成约束遗漏。

本次维护聚焦路径匹配器。原实现的字符匹配和路径段匹配均保留完整二维状态表，而计算下一步只需要上一行及当前行左侧状态。我将其改为单行滚动状态，保留原有匹配语义和公共接口，并补上独立递归判定器与长路径测试，验证优化没有改变策略判断。

### 预期使用场景

1. **合并前检查**：将变更清单、检查结果和审批证据送入工具，明确区分硬性拒绝与待补材料，而不是只返回笼统失败。
2. **目录迁移评审**：重命名同时关联迁出、迁入目录的规则，汇总负责人、审批数及检查项。
3. **规则调整验证**：对同一组路径比较新旧策略，检查责任人和约束变化；用版本化 JSON 接入后续流水线或留存审计结果。

## 核心功能范围

- 保留策略、变更及证据解析，路径通配符，负责人路由，检查与标签要求，行数预算，禁止操作、二进制限制及发布说明要求；提供 audit、audit-diff、explain、lint、compare 与文本/JSON 输出。
- **本次交付**：两层路径匹配状态压缩、4 个新增回归测试组、独立递归对照测试、维护说明和验证记录。原有 38 个测试组扩展为 42 个；字符层穷举 10,571 对、路径层穷举 2,520 对，共 13,091 对结果一致。新增测试在修改前实现上也通过，作为行为保持的交叉验证。
- **量化指标**：模式和输入均为 1,024 字符时，字符匹配状态从 1,050,625 个布尔槽降至 1,025 个，减少约 99.90%；双方均为 512 个路径段时，外层状态从 263,169 个降至 513 个，减少约 99.81%。这是由数组分配公式计算的辅助状态数量，不是进程内存实测，亦不宣称运行速度同比提高。
- **工程验证**：本地 wasm-gc、wasm、js 三目标严格检查及 42/42 测试通过；覆盖 1,024 字符、512 段路径及超限拒绝。清单 JSON 审计和 diff 审计示例均通过，公共接口无变化。native 本地静态检查通过，执行测试由 Ubuntu CI 验证；远程检查结果见维护 PR。
- **对标边界**：以 GitHub CODEOWNERS 的目录责任人工作流为参照，MoonChange 侧重将责任人与审批、检查、标签、预算等约束合并成可离线验证的评审计划；不是 CODEOWNERS 兼容解析器，也不替代 GitHub 分支保护。此次优化以项目原实现为定量基线，不用不同职责的软件做失真的速度排名。
- **明确不做**：生成或应用补丁、自动拉取 GitHub 审批、校验证据来源真实性、直接阻止平台合并。diff 上游不提供二进制标记，涉及二进制禁令时必须使用显式清单。
